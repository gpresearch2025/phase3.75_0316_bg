Consentext / Phase 3.75

Technical Brief

Consentext is the policy, routing, and audit layer between stored health context and every outbound AI or clinician-share action. It makes disclosure behavior explicit instead of implicit.

System boundary

Vault is the data plane. Trust kernel, policy engine, gateway, and audit are the control plane.

The main architectural choice is keeping stored health context separate from disclosure decisions so every outbound path is mediated, classified, and logged.

Core contract

Every request resolves to a lane with a disclosure class, an enforcement path, and an audit footprint.

The prototype is not just a prompt UI. It is a routing system that decides whether the request stays deterministic, uses an internal protected model, uses narrow governed external help, uses broader governed help, or leaves Consentext entirely.

Lane semantics

  • Deterministic: structured retrieval, no AI required.
  • Private: protected internal model only, no external disclosure.
  • Private+: minimum-necessary or de-identified governed export.
  • Max Intelligence: broader user-authorized governed export.
  • Off-Board: user leaves Consentext protections entirely.

Non-negotiable distinction

Private and Private+ are different technical contracts, not cosmetic labels.

Private requires an internal protected model inside Consentext-controlled systems. Private+ is the narrow external lane, with transform and scope reduction before outbound routing. Max Intelligence is a separate broader governed contract, not a synonym for Private+.

Policy object

  • Recipient type, verification status, and intended purpose.
  • Duration, pod scope, granularity, and identifier posture.
  • Outbound classification and share status.
  • Generated policy id, route summary, and append-only audit linkage.

Enforcement path

  • Policy evaluation selects route eligibility and output class.
  • Transforms reduce or block context before the gateway sees it.
  • The gateway mediates provider access through an adapter-ready layer.
  • Every route, share, revoke, and access check appends to audit.

Supporting surfaces

  • User-authorized clinician share exists before any promised staff portal.
  • Medication may remain in records and clinician packets, but medication guidance stays out of launch AI behavior.
  • Internal ops console supports route search, event filtering, and recent risk review.
  • Artifacts include policy JSON, audit summary JSON, clinician packet preview, PDF brief, and narrated walkthrough media.
  • Summary mode and light theme make the review easier without changing product logic.

Open implementation decisions

  • Protected internal model choice for the Private lane.
  • How many external providers the adapter layer should support in the first paid version.
  • Reference integration pattern for recipient verification and external APIs.
  • How far clinician workflows extend before a full portal becomes necessary.

Recommended review path

  • Start with the overview and control-plane framing.
  • Play the narrated walkthrough for the lane and trust-flow model.
  • Use scenario presets to inspect Private, user-authorized clinician sharing, Max Intelligence, and Off-Board behavior.
  • Finish in the workspace, ops console, audit surface, and artifact center.

Implementation takeaway

Consentext is a policy engine plus governed gateway in front of health-context use, with explicit lane contracts and audit proof.

The value is not only safer AI usage. The value is that disclosure logic becomes visible, consistent, and extendable without collapsing every request into the same trust posture.
