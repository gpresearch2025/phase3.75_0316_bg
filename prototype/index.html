      The governed request path

      1Select data

      Choose pods and categories from the vault.

      2Apply policy

      Set recipient, purpose, duration, and de-identification posture.

      3Route request

      Pick the correct lane based on privacy, capability, and control.

      4Review output

      Compare source context to the governed bundle.

      5Confirm audit

      Record the allow, deny, prepare, and access decisions.

      Scope Clarification

      What this phase is and is not

      Phase 3.75 is

      • Trust boundary definition
      • Consent engine and policy evaluation
      • De-identification and privacy safeguards
      • AI gateway architecture
      • Outbound governance and audit traceability

      Phase 3.75 is not

      • Automatic rebuild of the dashboard or portal
      • Full wearable or EHR integration pass right now
      • Final model-vendor strategy
      • Judgment that every prior component must be replaced

                1. Vault-backed tracker views
                Charts and tables should read through vault contracts, not bypass them.
                
          
                2. Consent and share lifecycle
                Create, preview, revoke, and audit every outbound share object.

                Derived-first, deterministic bundle generation with recipient-specific rules.
                
          
                4. AI gateway routing
                Classify prompt, select lane, minimize context, and record the decision.
                
          
                5. API gateway enforcement
                Verify recipient, enforce scope, issue decision, and fail closed.
                
          
                6. Audit viewer
                Make the trust trail legible to the user, not only to operators.
